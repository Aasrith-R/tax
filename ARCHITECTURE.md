# Архитектура приложения

## Обзор

Приложение состоит из двух частей:
1. **Фронтенд** - React + TypeScript + Vite
2. **Бэкенд** - Express.js + TypeScript + Prisma + PostgreSQL

## Фронтенд

### Структура
- `src/components/` - React компоненты
  - `auth/` - Формы входа и регистрации
  - `dashboard/` - Компоненты дашборда (таблицы, графики)
  - `reports/` - Список отчетов
  - `upload/` - Загрузка файлов
- `src/services/` - API клиент для взаимодействия с бэкендом
- `src/lib/vat.ts` - **КРИТИЧЕСКИ ВАЖНО**: Алгоритм расчета НДС (НЕ МЕНЯТЬ)
- `src/types/` - TypeScript типы

### Состояние приложения
- Аутентификация через JWT токены (хранятся в localStorage)
- Три основных view:
  - `auth` - Вход/регистрация
  - `reports` - Список отчетов пользователя
  - `dashboard` - Просмотр и редактирование отчета

## Бэкенд

### Структура
- `server/src/routes/` - API маршруты
  - `auth.ts` - Аутентификация (register, login, me)
  - `reports.ts` - CRUD операции с отчетами
- `server/src/middleware/` - Middleware
  - `auth.ts` - Проверка JWT токенов
  - `errorHandler.ts` - Обработка ошибок
- `server/prisma/` - Prisma схема и миграции

### База данных

#### User (Пользователи)
- `id` - CUID
- `email` - Уникальный email
- `password` - Хешированный пароль (bcrypt)
- `name` - Имя пользователя (опционально)
- `createdAt`, `updatedAt` - Временные метки

#### Report (Отчеты)
- `id` - CUID
- `userId` - Связь с пользователем
- `title` - Название отчета
- `status` - Статус: `REQUIRES_REVIEW` или `READY`
- `totals` - JSON с итогами (input_vat, output_vat, net_vat)
- `createdAt`, `updatedAt` - Временные метки

#### Operation (Операции)
- `id` - CUID
- `reportId` - Связь с отчетом
- `date` - Дата операции
- `amount` - Сумма операции
- `vatRate` - Ставка НДС
- `vatAmount` - Сумма НДС
- `counterparty` - Контрагент
- `source` - Источник (имя файла)
- `direction` - Направление: `input` или `output`
- `errors` - JSON массив ошибок валидации

## API Endpoints

### Аутентификация
- `POST /api/auth/register` - Регистрация
- `POST /api/auth/login` - Вход
- `GET /api/auth/me` - Текущий пользователь

### Отчеты (требуют аутентификации)
- `GET /api/reports` - Список отчетов пользователя
- `GET /api/reports/:id` - Получить отчет с операциями
- `POST /api/reports` - Создать отчет
- `PATCH /api/reports/:id/status` - Обновить статус
- `DELETE /api/reports/:id` - Удалить отчет

## Безопасность

- Пароли хешируются с помощью bcrypt (10 раундов)
- JWT токены с истечением через 7 дней
- Все запросы к отчетам проверяют принадлежность пользователю
- CORS настроен для фронтенда

## Статусы отчетов

- **REQUIRES_REVIEW** (Требует просмотра) - По умолчанию при создании
- **READY** (Готов) - Устанавливается пользователем после проверки

## Поток данных

1. Пользователь загружает файл Excel/CSV
2. Фронтенд парсит файл и вычисляет НДС (используя `lib/vat.ts`)
3. Пользователь вводит название и сохраняет отчет
4. Фронтенд отправляет данные на бэкенд
5. Бэкенд сохраняет отчет и операции в БД
6. Пользователь может просматривать, редактировать и менять статус отчетов

## Важные замечания

- **НЕ МЕНЯТЬ** `src/lib/vat.ts` - это критически важный алгоритм расчета НДС
- Все операции привязаны к отчетам
- Отчеты привязаны к пользователям
- При удалении отчета каскадно удаляются все операции
